# Finder implementation plan

Build the supplied Large files, Old downloads and Duplicates brief in the existing WinForms/WebView2 architecture. Keep scanning and removal in a new Finder feature; reuse the existing progress, confirmation, size and deletion helpers.

1. Add failing temp-folder tests for thresholds, protected paths, download ages/types, staged duplicate detection, hard links, scan-only removal and the keep-one rule.
2. Implement focused Finder models, enumeration/rules, Windows known-folder/file-identity helpers, staged hashing and a service with scan snapshots. Serialize scans/removals and revalidate changed files before recycling. Never delete real user data in tests.
3. Add scoped RPC methods and stream events. Add a separate Finder action module and three-tab view after Explore, with selection, progress, cancellation, exact confirmations and host/UI keep-one enforcement.
4. Update the README cleaning table. Run Finder tests, the complete test suite, the app build and syntax checks for each changed JavaScript file. Review the final diff and commit with `feat: add large files downloads and duplicate finder`; do not push or bump the version.

Review focus: overlapping roots, inaccessible files, canceled or replaced scans, files changing while hashed, stale selections, concurrent removals, missing keeper copies and redirected Downloads folders. Use allocated size for displayed space and logical size for duplicate hashing buckets. Skip linked folders and cloud-only files during content hashing.
